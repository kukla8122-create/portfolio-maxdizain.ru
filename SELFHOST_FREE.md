# МАКСимум мебель — самостоятельный MAX-бот без платного конструктора

Рабочая ветка: `maxbot-production`.

Главный стандарт: `docs/MAX_BOT_IMPLEMENTATION_2026-08.md`.

## Что запускается

Production запускается через `maxbot-entry.py`, который загружает основную бизнес-логику из `maxbot-selfhosted.py`.

Возможности:

- API: `https://platform-api2.max.ru`;
- production Webhook: `POST /webhook`;
- `GET /health` — процесс жив;
- `GET /ready` — токен MAX принят и точный Webhook зарегистрирован;
- `GET /storage` — безопасная проверка постоянства `/app/data` между перезапусками;
- проверка `X-Max-Bot-Api-Secret`;
- callback-кнопки + `POST /answers`;
- `request_contact` и HMAC-SHA256-проверка номера;
- заявки на кухню, шкаф и дизайн-проект;
- FAQ и сохранение нестандартных вопросов;
- SQLite: `/app/data/maxbot.db`;
- 20 фото портфолио с `portfolio-maxdizain.ru`;
- сохранение `chat_id` канала/чата по событию `bot_added`;
- защита от очевидных повторных webhook-доставок в рамках процесса.

## Секреты

НИКОГДА не добавлять токены в Git и не отправлять их в чат.

Код понимает оба имени токена:

```text
MAX_BOT_TOKEN=<реальный токен MAX>
```

или, если панель хостинга сама создаёт стандартную переменную:

```text
BOT_TOKEN=<реальный токен MAX>
```

`MAX_WEBHOOK_SECRET` можно задать вручную, но это не обязательно: если переменной нет, `maxbot-entry.py` безопасно выводит допустимый webhook-secret из MAX-токена. Сам токен при этом нигде не публикуется.

Хостинг задаёт `PORT`; приложение слушает `0.0.0.0:$PORT`.

Для публичного адреса используется автоматически предоставленная хостингом переменная `DOMAIN` либо вручную заданный `PUBLIC_BASE_URL`.

## Docker

В корне ветки есть `Dockerfile`. Он:

1. использует Python 3.12 slim;
2. устанавливает системные CA и `curl`;
3. добавляет корневой и промежуточный сертификаты Минцифры;
4. копирует `maxbot-entry.py` и `maxbot-selfhosted.py`;
5. запускает `python /app/maxbot-entry.py`;
6. не требует сторонних Python-пакетов.

CI автоматически проверяет:

- компиляцию Python;
- unit-тесты;
- полную сборку Docker-образа;
- размер образа меньше 450 MB;
- запуск контейнера с лимитами 192 MB RAM и 0.5 CPU;
- `/health`;
- `/storage`.

## Бесплатное размещение: Bothost Starter — только после фактической проверки панели

У Bothost есть противоречие в публичных материалах: общая страница Starter заявляет Docker + SSL Webhooks за 0 ₽, а отдельная MAX-страница перечисляет Webhook integration у Business. Поэтому НИЧЕГО НЕ ОПЛАЧИВАЕМ и сначала проверяем фактические возможности бесплатного аккаунта.

Параметры проекта:

```text
Git repository: https://github.com/kukla8122-create/portfolio-maxdizain.ru.git
Branch: maxbot-production
Custom Dockerfile: ON
Use domain: ON — только если доступно бесплатно
Internal port: значение PORT в панели; код читает его автоматически
```

Токен MAX вводится только в защищённое поле панели/переменную окружения. В чат его не присылать.

После первого деплоя:

1. открыть `https://<домен>/health` → `"ok": true`;
2. подождать автоподписку MAX;
3. открыть `https://<домен>/ready` → все четыре флага должны показывать готовность (`ok`, `max_api`, `webhook`, `public_url_configured`);
4. открыть `https://<домен>/storage` и сохранить `probe` + `boot_count`;
5. перезапустить контейнер из панели;
6. снова открыть `/storage`: `probe` должен остаться тем же, `boot_count` — увеличиться. Это подтверждает реальную персистентность бесплатного `/app/data`;
7. только затем тестировать личный диалог MAX, 8 кнопок, заявки и `request_contact`;
8. только после успешного личного теста добавлять бота в канал.

Если бесплатный Starter не даёт публичный HTTPS-домен/Webhook или не сохраняет `/app/data` между перезапусками, НИЧЕГО НЕ ОПЛАЧИВАТЬ. Этот вариант не принимаем как production и выбираем следующую бесплатную схему.

## Канал MAX

Заявки ведём в личном диалоге с ботом. Канал используется как точка входа и для публикаций.

Webhook подписан на `bot_added`; после добавления в канал бот сохраняет `chat_id` и `is_channel` в SQLite. Права администратора выдаются только те, которые реально нужны сценарию.

## ИИ

Платный конструктор и платный GigaChat для первой production-версии не нужны. Ветка «Задать вопрос»:

- отвечает на известные FAQ;
- сохраняет нестандартный вопрос для Катерины.

AI подключается позже как отдельный заменяемый модуль, только на подходящих коммерческих условиях и с минимизацией персональных данных.

## Переключение со старого решения

- Production MAX = Webhook.
- Long Polling и Webhook одновременно не используем.
- Старый VPS не удаляем до успешного теста нового сервиса.
- После успешного запуска проверяем `GET /subscriptions` и убираем старую webhook-подписку, если она существует.
- При подозрении на утечку токена перевыпускаем его в MAX для бизнеса и обновляем только секрет в панели хостинга.
