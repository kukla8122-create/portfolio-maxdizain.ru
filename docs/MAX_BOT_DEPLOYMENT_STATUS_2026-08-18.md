# MAX bot — статус размещения 18.08.2026

Главный стандарт: `docs/MAX_BOT_IMPLEMENTATION_2026-08.md`.

## Bothost — фактическая проверка кабинета

Проверен реальный личный кабинет пользователя на бесплатном тарифе.

Фактический статус:
- тариф аккаунта: «Бесплатный»;
- в кабинете показано уведомление: «Бесплатный тариф пока отключен из-за отсутствия лишних мощностей»;
- раздел «Git репозитории» помечен как доступный на платных тарифах;
- поэтому Bothost не использовать для production сейчас;
- ничего не оплачивать только ради продолжения этой проверки.

Решение принято согласно `MAX_BOT_IMPLEMENTATION_2026-08`: бесплатный кандидат должен быть проверен фактически до оплаты; если нужные production-возможности недоступны — перейти к следующему варианту.

## Следующий кандидат — Cloud.ru Evolution Container Apps

Проверены официальные материалы Cloud.ru на 18.08.2026.

Подходит по архитектуре:
- Container Apps запускает Docker-образы;
- можно получить автоматически генерируемый публичный HTTPS URL;
- поддерживаются переменные окружения и секреты;
- поддерживаются постоянные тома на базе Object Storage, в документации SQLite прямо указан как пример использования постоянного тома;
- Container Services поддерживает масштабирование до 0 экземпляров;
- есть ежемесячный free tier: первые 25 vCPU×ч и первые 50 ГБ RAM×ч для Container Services;
- Object Storage также имеет free tier, пригодный для небольшого persistent volume;
- Docker-образ для Container Apps размещается в Artifact Registry.

Ограничение:
- free tier Cloud.ru — это бесплатный месячный объём ресурсов, а не безлимитная 24/7 виртуальная машина;
- поэтому для малонагруженного MAX webhook использовать `min instances = 0`, `max instances = 1` и минимальную конфигурацию;
- после реального деплоя обязательно проверить время холодного старта: MAX требует HTTP 200 от Webhook не позднее 30 секунд;
- если cold start систематически нарушает это требование или фактическая тарификация выходит за free tier, Cloud.ru не принимать как production-бесплатный вариант.

## Неизменные правила MAX

По актуальной официальной документации MAX:
- API: `https://platform-api2.max.ru`;
- production — Webhook;
- Long Polling и Webhook одновременно не использовать;
- Webhook — HTTPS, внешний порт 443, доверенный TLS;
- если указан secret, проверять `X-Max-Bot-Api-Secret`;
- endpoint должен вернуть HTTP 200 в течение 30 секунд;
- токен передавать только заголовком `Authorization`.

## Следующий шаг

1. Создать/открыть аккаунт Cloud.ru Evolution.
2. Проверить, что Container Apps, Artifact Registry и Object Storage доступны в аккаунте без обязательной платной подписки для первоначального теста.
3. Ничего не пополнять и не привязывать платный сценарий без необходимости.
4. После доступа к кабинету создать Artifact Registry и настроить безопасную загрузку уже проверенного Docker-образа из ветки `maxbot-production`.
5. Затем создать Container Service с публичным URL, секретом MAX, persistent volume и масштабированием 0→1.
6. Проверить `/health`, `/ready`, `/storage`, cold start и фактический Webhook MAX.
