# МАКСимум мебель — правильное внедрение бота в MAX
## Единый рабочий стандарт на август 2026

Дата фиксации: 18.08.2026
Статус: источник правды для дальнейшей разработки и внедрения.

> При любых будущих изменениях сначала сверять актуальную официальную документацию MAX (dev.max.ru). Если сторонняя статья расходится с официальной документацией — приоритет у MAX.

## 1. Цель проекта

Создать и запустить собственного бизнес-бота «МАКСимум мебель» в мессенджере MAX без платных конструкторов и посредников.

Бот должен:
- работать в личном диалоге с клиентом;
- иметь главное меню и кнопки;
- рассказывать о компании;
- собирать заявки на кухню, шкаф и дизайн-проект;
- показывать работы;
- показывать контакты;
- принимать свободный вопрос;
- сохранять заявки;
- по возможности получать подтверждённый номер телефона через MAX;
- в перспективе подключать AI через отдельный сменный модуль;
- быть связан с каналом «МАКСимум мебель», но не смешивать публичный канал и личные заявки клиентов.

## 2. Актуальный MAX API

Использовать только:

https://platform-api2.max.ru

С 19 июля 2026 старый домен platform-api.max.ru считается устаревшим для корректной работы ботов и мини-приложений.

Токен бота:
- передавать только в HTTP-заголовке Authorization;
- не передавать в query-параметрах;
- не хранить в GitHub;
- не показывать в скриншотах, логах и чатах;
- хранить только в секретах/переменных окружения хостинга.

На стороне ОС/контейнера должны быть доверены актуальные сертификаты Минцифры.

## 3. Webhook — обязательная production-схема

Для production использовать Webhook.

Long Polling:
- допустим только для разработки и тестирования;
- ограничен по скорости и хранению событий;
- не подходит для production;
- нельзя использовать одновременно с Webhook.

Регистрация Webhook:
POST /subscriptions

Webhook должен:
- быть доступен по HTTPS;
- использовать доверенный TLS-сертификат;
- быть доступен извне на стандартном HTTPS-порту 443;
- быстро отвечать HTTP 200;
- обрабатывать тяжёлую логику асинхронно/через очередь;
- проверять X-Max-Bot-Api-Secret, если задан secret;
- не светить secret в логах.

## 4. События и chat_id

Начиная с июня 2026 метод GET /chats больше не поддерживается как старый способ получения списка чатов/каналов.

chat_id чата или канала нужно получать через события подписки Webhook, например:
- bot_added;
- bot_started;
- другие Update-события.

ID канала нужно сохранить в нашей базе при первом получении события bot_added с признаком канала.

## 5. Работа с каналом MAX

Канал и личный диалог с ботом — разные сущности.

Правильная бизнес-схема:
1. Пользователь видит канал «МАКСимум мебель».
2. Из канала переходит к боту/ассистенту.
3. Заявка и персональные данные собираются в личном диалоге пользователя с ботом.
4. Бот может быть добавлен администратором канала для автоматических публикаций и других разрешённых действий.

Не собирать индивидуальные заявки клиентов прямо в публичном канале.

## 6. Кнопки MAX

Для меню использовать inline_keyboard.

Главное меню проекта:
1. 🏠 Кто мы
2. 🍽 Заказать кухню
3. 🚪 Заказать шкаф
4. 📐 Дизайн-проект
5. 💰 Узнать стоимость
6. 🖼 Наши работы
7. 📞 Наши контакты
8. 💬 Задать вопрос

Для надёжности и удобства длинные подписи лучше размещать по одной кнопке в строке.

Для callback-кнопок после нажатия отправлять ответ на callback через POST /answers, чтобы у пользователя не зависал индикатор ожидания.

## 7. Получение телефона клиента

MAX поддерживает кнопку request_contact.

Использовать её как основной удобный способ получить номер, привязанный к аккаунту пользователя.

При получении contact-вложения:
- извлечь vcf_info;
- извлечь hash;
- проверить подпись HMAC-SHA256 с использованием токена бота;
- сохранить признак, подтверждён ли номер MAX.

Также оставить запасной вариант: пользователь может написать номер вручную.

## 8. Сценарии заявок

### Кухня
Собирать:
- имя;
- город;
- размеры помещения/кухни;
- пожелания по стилю, цвету, технике и планировке;
- телефон.

### Шкаф
Собирать:
- имя;
- город;
- тип шкафа;
- примерные размеры;
- пожелания по наполнению;
- телефон.

### Дизайн-проект
Собирать:
- имя;
- город;
- площадь и помещения;
- пожелания;
- телефон.

После сохранения показывать подтверждение:
«Спасибо! Заявка принята ✅ Катерина свяжется с Вами и уточнит детали.»

## 9. Хранение данных

Для первой production-версии достаточно SQLite.

Хранить:
- sessions — состояние текущего диалога;
- leads — заявки;
- channels — найденные чаты/каналы;
- settings — служебные настройки.

База должна располагаться в persistent storage хостинга, а не во временной файловой системе контейнера.

## 11. Архитектура AI

Правильная архитектура:

MAX Bot API → Webhook → наш backend → детерминированная бизнес-логика + база знаний/контекст → AI API → ответ в MAX.

AI должен быть отдельным сменным адаптером, чтобы можно было заменить модель без переписывания MAX-интеграции.

Не отдавать AI критичные решения:
- точные цены;
- скидки;
- сроки;
- договорные обязательства;
- действия с персональными данными.

Критичные данные должны приходить из проверенного источника или жёсткой логики кода.

## 12. Защита от галлюцинаций

Для AI нужны:
- строгий системный промпт;
- база знаний/RAG по материалам «МАКСимум мебель»;
- короткая память диалога;
- правило «не знаешь — не придумывай»;
- fallback на Катерину;
- тестирование на провокационные и ошибочные вопросы.

Цены и обязательства AI не генерирует из памяти.

## 13. Персональные данные и AI

Не отправлять в нейросеть лишние персональные данные.

Телефон, адрес и иные ПД хранить отдельно и передавать AI только если это действительно необходимо.

Перед полноценным коммерческим запуском предусмотреть:
- уведомление, что пользователь общается с ботом;
- политику конфиденциальности;
- согласие/правовое основание на обработку персональных данных;
- минимизацию данных;
- российский hosting/backend для обработки ПД, если это требуется применимым законодательством.

## 14. GigaChat / YandexGPT

GigaChat и YandexGPT технически подходят как AI-модули.

Но бесплатный GigaChat Freemium нельзя считать легальным постоянным бесплатным решением для коммерческого бизнес-бота: официальные условия требуют проверять коммерческий тариф/пакет.

Yandex Cloud может давать стартовые гранты новым пользователям, но это временный грант, а не вечный бесплатный AI.

Поэтому production-бот должен уметь работать и без AI:
- FAQ — детерминированно;
- неизвестный вопрос — сохранить и передать Катерине;
- AI подключать отдельно, когда выбран законный и экономически подходящий вариант.

## 15. Хостинг

Нужен хостинг, который позволяет:
- Docker или Python-приложение;
- публичный HTTPS URL;
- webhook на 443;
- переменные окружения/секреты;
- persistent storage для SQLite;
- исходящие HTTPS-запросы к platform-api2.max.ru;
- доверенные сертификаты Минцифры.

При выборе бесплатного тарифа сначала фактически проверять панель и ограничения. Не оплачивать конструкторы до теста.

## 17. Безопасность

Никогда не хранить в репозитории:
- MAX_BOT_TOKEN;
- MAX_WEBHOOK_SECRET;
- GigaChat/YandexGPT ключи;
- LEADTEX/другие API-ключи;
- пароли VPS/хостинга.

Секреты — только environment variables / secret storage.

При подозрении на утечку токена — перевыпустить токен в кабинете MAX.

## 19. Что считать устаревшим и не использовать

Не использовать без отдельной свежей проверки:
- platform-api.max.ru;
- передачу токена в query;
- GET /chats как старый способ получения списка чатов;
- сторонние инструкции с api.max.ru/method/groups.addBot или groups.setCallbackServer как замену текущему официальному MAX Bot API;
- Long Polling как production-модель;
- платный конструктор как обязательное условие запуска.

## 20. Порядок дальнейшего внедрения

1. Выбрать и проверить бесплатный/минимальный hosting, соответствующий требованиям MAX.
2. Развернуть ветку maxbot-production.
3. Задать секреты через переменные окружения.
4. Проверить /health.
5. Проверить исходящий GET /me к platform-api2.max.ru.
6. Зарегистрировать Webhook через POST /subscriptions.
7. Убедиться, что Webhook получает события и возвращает 200.
8. Проверить /start и главное меню.
9. Проверить все callback-кнопки и POST /answers.
10. Проверить заявки кухня/шкаф/дизайн.
11. Проверить request_contact и ручной номер.
12. Проверить сохранение SQLite после перезапуска.
13. Проверить портфолио.
14. Добавить бота в канал и получить chat_id через событие bot_added.
15. Проверить права администратора канала только в объёме, необходимом для задачи.
16. Только после стабильной работы отключить старый Long Polling/VPS-процесс, чтобы не было конкуренции за события.
17. Отдельно решить вопрос AI и персональных данных.
